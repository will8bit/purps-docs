## Errors

Every failure is `{ "ok": false, "error": "…" }` with a short reason in plain words and a matching HTTP status:

| Status | Meaning |
| --- | --- |
| `400` | Something in the request is wrong. The reason says what. |
| `401` | The signature is invalid, its timestamp is too old, or the nonce was not issued for this wallet and action. |
| `403` | The wallet may not do this yet, the feature is not open, or the address is blocked. |
| `404` | The coin or launch does not exist. |
| `409` | The action does not fit the coin's state. |
| `410` | An old `/api/v1` write address. Use `/api/v2`; v1 reads still answer. |
| `413` | The body is too large. |
| `422` | The strategy, its parameters or a money check fail validation. The reason says why. |
| `423` | Creator authority on the coin is frozen. |
| `429` | Too many requests (the per-minute limiter adds `Retry-After`; the hourly budgets and creator-authority cooldowns say how long in the reason). |
| `500` | Something broke on our side. Try again. |
| `503` | We could not reach something we depend on, the site is mid-deploy, or the API is paused. |

A `503` with a `Retry-After` header and the reason `the public API is paused for maintenance — check back soon` means the whole API is switched off for a while. Nothing is wrong with your request; come back after the wait.

## Rate limits

Limits are per address (IPv6: per /64 block) and per endpoint, in one-minute windows. Every answer from the API itself says what the limit is (the 503 while paused and the 410 on old v1 addresses carry no limit headers):

```
RateLimit-Limit: 60
RateLimit-Policy: 60;w=60
```

Responses that are not cached (writes, `prepare` and `submit`, every refusal) also say where you stand:

```
RateLimit-Remaining: 41
RateLimit-Reset: 23
```

Cacheable reads leave those two out on purpose: an edge cache would otherwise hand one caller's remaining allowance to the next. A `429` from the per-minute limiter adds `Retry-After`; the others say how long in the reason. Each endpoint's limit is on its reference page. Reads may be cached at the edge for a few seconds, so two calls in a row can return the same figures; writes are never cached.

Hourly budgets sit on top of the per-minute limits, and their `429` says so in the reason. Launch builds: 8 an hour per wallet, 20 an hour per address, 240 an hour site-wide, on purps.lol and on pump.fun each; a new fee level on purps.lol needs its own on-chain setup and is allowed 2 an hour per address and 6 an hour site-wide. Fetching a logo by `imageUrl`: 20 an hour per address, 200 an hour site-wide; when that runs out the build asks for `image` as a data URL instead, which is never budgeted. Pons: 10 launch builds and 20 registrations an hour per wallet. Creator authority: 60 actions, 30 strategy changes, 10 requests and 20 handovers an hour per address, plus a per-coin count of position actions a day and a cooldown after each change; the limit and the running cooldowns are reported on `GET /coins/{mint}/authority`.
